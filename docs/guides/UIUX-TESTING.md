# UIUX 整體測試規範

## Site assets CDN／本地備援（2026-10-20）

隔離元件頁以可控的本機HTTP圖片代表主要來源，確認：主要來源成功時保持主要圖；主要圖404時改用本地圖且正常載入；由失敗來源改成成功來源後重新顯示主要圖；主要與備援皆404時停在備援src、不來回改寫。元件測試頁不是正式路由，不放交付包。

Home／About各在375／768／1440px檢查，共6組；各頁網站素材全部載入、未量到水平溢出，Home三張分類連結維持DeskLiving／SpaceStyling／BalconyMood。實際預覽時六個配置的CDN網址皆落入本地備援，故此輪不宣告正式ImageKit圖片已上傳或可達。上傳後應再以Network／圖片目前src確認走CDN，而不是僅看畫面有圖。

重測時可暫時阻擋指定CDN圖片確認備援，再恢復網址並重整確認優先來源；不要把測試用localhost路徑填入正式資料。檢查About故事3:2／生活1:1／結尾取景與Home原版型不變。

## Articles 初版檢查紀錄（2026-10-18）

本次於隔離 mock 預覽檢查，未操作正式 API 寫入。正常根字級 16px 與加倍根字級 32px 各測 320、375、414、768、1024、1440px，共 12 組；另測 575／576／577、767／768／769、991／992／993、1295／1296／1297px 共 12 組正常字級斷點情境。未量到水平溢出、main／Footer 重疊或 Header 遮住 Hero 文字，標題與列表左緣對齊。正常字級 Hero 為 320px；放大文字可自然長高。

重測方式：

1. 開啟 `/articles`，確認圖片延伸至頁頂、main 沒有重複的頂部留白，圖片淡入「最近的植栽提案」背景。
2. 檢查 Hero 背景不因 hover 放大；Header 保持原頂部透明／hover 顯色、下捲隱藏策略。
3. 手機開啟選單時背景鎖定；Escape 關閉後恢復捲動。桌機檢查導覽仍可切頁。
4. 使用至少 7 篇公開文章檢查每頁 6 篇，切第 2 頁、詳情底部返回、重新整理後仍為第 2 頁，返回列表標題並保留焦點。本次以本機 30 篇 fixture 抽查。
5. 初版曾在 375／1440px 抽查 Home、About、產品目錄、歷次訂單，未量到水平溢出。初版只有 Articles 啟用 subpage；現行產品目錄與歷次訂單亦使用同一變體，依上方 v2 尺度重測。

加倍根字級不等於真正瀏覽器縮放或 iPhone Safari 驗收；真機、安全區與正式交易等保留到最後整合驗收。

## 尺寸與環境

- 基本寬度：375、414、768、1024、1440px。
- 前台斷點前後：575／576／577、767／768／769、991／992／993、1295／1296／1297px。
- 連續拖曳寬度，尤其 1024～1440px；同時看短視窗、手機橫向與實際裝置。
- 記錄 viewport 寬高、根字級、瀏覽器與資料版本；不能只留截圖寬度。
- safe-area 由瀏覽器與顯示模式提供，可能為 0。手機尺寸模擬不等於 iPhone 動態島／Safari／主畫面模式實機驗證。

## Header、Hero 與全站版面

| 測試 | 通過條件 |
|---|---|
| 首次／F5 進 Hero 頁 | 頂部透明、內容與 CTA 完整 |
| Hero Header hover／離開 | 顯色與恢復正確，不改變捲動位移 |
| 超過 150px 向下／向上 | Header 隱藏／顯示符合規則 |
| 點 Logo、切頁返回、上一頁／下一頁 | 不殘留上一頁背景、捲動狀態或選單 |
| 鍵盤操作同一路徑 | 焦點提示清楚，不造成整條 Header 錯誤實色 |
| 非 Hero 頁 | 正文不被 fixed Header 擋住，留白對應 100／116px |
| ProductDetail sticky／商品錨點 | 不被 Header 遮擋 |
| 手機開關選單、Escape、Tab、切頁／轉桌機 | 隱藏入口不可聚焦，焦點與背景捲動鎖清理正常 |
| Footer／短內容頁／GoTop | 版權與入口可用，沒有內容重疊或錯誤高度裁切 |

Hero 的每張 slide 分別檢查背景裁切、文字、CTA、層級與 Tab 可達性。減少動態時內容一開始可見，不依賴動畫播放完成。`/articles` 依現有 Header／FrontLayout 分工判讀，不在測試中自行統一路徑配置。

## 水平溢出

比較 documentElement 的 scrollWidth 與 clientWidth，並定位實際超界元素。於首次動畫前、動畫中、選單開關與切頁後都檢查；垂直捲軸占寬不等同 X 軸錯誤。

BrandStory 應為 fade-up，Swiper 內部位移不能擴大整頁。不要用全頁 overflow-x:hidden 作為通過測試的依據。

## 資料與頁面流程

- 商品列表／詳情檢查長標題、圖片、價格、換行、無圖 fallback 與啟用狀態。
- 首頁精選與 Seasonal 分開，符合 6–8 筆選擇規則，不以普通商品湊數。
- Article 用合格公開候選測人工入選、排序、補位與一大兩小；下架日當天有效、隔日排除。
- 列表與詳情資料邊界分開判讀，不以列表缺正文推定單篇空白。
- 購物車、付款與完成頁、Customer Orders 的操作結果與通知一致；錯誤資訊可在頁面理解，避免只剩短暫 Toast。
- 空資料、載入、失敗與正常資料都要有可理解的顯示；測試資料使用去識別內容。

## Toast 外觀與互動

開發預覽網址與按鈕說明見 [Toast 文件](TOAST.md)。

| 案例 | 通過條件 |
|---|---|
| 四種狀態、淺色頁／Hero／Header 背景 | 圖示、標籤、邊框與正文可辨認 |
| 短／長／換行／長編號 | 高度自然增長，不橫向溢出，X 不被擠掉 |
| 單則自動離場 | 進場後完整 5／7 秒，再播放離場 |
| hover 停留後離開 | 暫停並接剩餘時間，至少保留 2 秒 |
| hover＋鍵盤焦點重疊 | 只解除其中一個原因不能恢復 |
| 切換分頁／視窗 | 返回時接續剩餘時間，不保留錯誤 hover 原因 |
| 暫停時新增通知 | 原卡片不重播、不偷恢復倒數 |
| 五則排隊 | 同時最多三則，排隊取得完整閱讀時間 |
| 連點 X／進場中關閉／離場中 hover | 不重複移除、不復活 |
| 鍵盤關閉／手機觸控 X | 焦點合理，其他通知不因觸控焦點永久停住 |
| 減少動態 | 純淡入淡出，內容持續可讀 |
| production build | 原 query 不開啟開發面板，正式通知仍可用 |

清除測試樣本可避免固定通知占住名額。三則長訊息也應在矮畫面觀察，數量上限本身不保證任何內容高度都可見。

## 計時自動回歸

在 VS Code 新增終端機，位置為含 package.json 的專案根目錄；不要在正在跑開發伺服器的同一個輸入程序內執行。

```powershell
node --test --test-reporter=spec docs/guides/scripts/TOAST-LIFECYCLE-REGRESSION-v2.test.mjs
```

目前腳本預期 tests 19、pass 19、fail 0。使用 Node 原生測試與模擬時鐘，不需要安裝額外套件，不會打開網站，也不必等待每次真實 5／7 秒。

腳本依相對路徑讀取 `src/features/ui/toastLifecycle.js`，不能單獨抽出執行。修改生命週期或動畫階段時間時，對照並更新測試預期。

這個腳本驗證計時、暫停、排隊、重複移除與清理；不能驗證 React DOM 事件、實際動畫、圖片、鍵盤行為、對比或手機安全區。
