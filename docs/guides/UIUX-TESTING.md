# UIUX 測試方法與通過條件

本文件保存可重複執行的測試方式，不保存私人計畫、逐次交付歷史或本人驗收紀錄。預期行為以 [功能文件](FRONT-FEATURES.md)、[版面規範](../specs/FRONT-LAYOUT-INTERACTION-RULES.md) 與現行程式為準；文件存在不代表所有情境已驗收。

## 環境與尺寸

- 基本寬度：320、375、414、768、1024、1440px。
- 斷點前後：575／576／577、767／768／769、991／992／993、1295／1296／1297px；也應連續拖曳寬度觀察重排。
- 同時觀察短視窗、手機橫向、正常／放大文字及實際裝置，記錄 viewport 寬高、根字級、瀏覽器、版本與資料來源。
- 加倍根字級不等於真正瀏覽器縮放；手機尺寸模擬不等於 Safari、安全區或主畫面模式的實機驗收。
- 使用去識別測試資料；隔離 mock 與正式 API 的測試結果分開記錄，不以版面檢查操作正式交易。

## Header、Footer 與頁面骨架

| 測試 | 通過條件 |
|---|---|
| 首次、重整或切換至 Hero 頁 | Header 頂部狀態正確，正文與 CTA 完整 |
| Header hover／離開、超過 150px 上下捲動 | 背景與顯示／隱藏符合規範，hover 不改變捲動位移 |
| Logo、導覽、瀏覽器前進／返回 | 不殘留上一頁背景、選單或錯誤捲動狀態 |
| 鍵盤操作 | 焦點清楚，不強制整條 Header 留在錯誤狀態 |
| 非 Hero 頁 | 正文不被 fixed Header 擋住，預留空間符合共用 token |
| 商品詳情、區塊錨點 | 內容可自然捲動，目標不被 Header 遮住 |
| 手機選單開關、Escape、Tab、切頁、轉桌機 | 隱藏入口不可聚焦，背景鎖定與焦點返回清理正確 |
| 短頁、長頁、空資料與 Footer | 沒有內容重疊或高度裁切，版權與功能入口可用 |
| GoTop | 獨立入口可用，回到正確位置，不依賴 Footer 定位 |

## Hero 與 About

- 每張 Home slide 分別檢查圖片裁切、文字、CTA、層級與 Tab 可達性；非作用中 slide 不應留下可聚焦入口。
- 三頁短 Hero 檢查文字與 main 左緣對齊、無重複頂部留白、底部銜接自然、背景不因 hover 放大。
- 短 Hero 最小高度按 320／336／360px 尺度判斷，文字換行或放大時允許自然長高，不以固定高度裁切。
- 完整捲動 About，檢查故事圖片、左右交錯／手機上下排列、生活卡網格與結尾文案可讀性。
- About 生活卡在平板兩欄且第三卡置中、桌機三欄；文字放大時內容不超出卡片。
- About 卡片以滑鼠 hover、鍵盤聚焦及移開測試整卡縮放、陰影與薄幕還原；手機直接顯示必要資訊與閱讀入口。
- 一般模式確認分組淡入與單次播放；減少動態效果時，內容一開始可見且不依賴動畫完成事件。

## 圖片主要來源與本地備援

以可控測試來源分別確認：

1. 主要來源成功時保持主要圖。
2. 主要圖載入失敗時切到本地圖，並確認實際載入成功。
3. 失敗的來源組合改成可用來源後，重新嘗試主要來源。
4. 主要與本地都失敗時，不反覆切換或形成請求迴圈。
5. 圖片未載入、載入完成及切換備援後，文字與版面不被裁切。

實際頁面可暫時阻擋指定 CDN 圖片確認備援，再恢復並重整。用 Network 或目前圖片 `src` 區分遠端成功與本地備援，不以「畫面有圖」推定 CDN 可達。測試用 localhost 路徑不得寫入正式資料。

核對 `siteAssets.js` 的本地 import、CDN 相對路徑、上傳目錄與實際副檔名；環境變數切換後，分別確認開發環境重啟與部署產物。替換圖片時檢查手機／平板／桌機裁切，不只核對 URL。

## 水平溢出與重排

比較 `document.documentElement.scrollWidth` 與 `clientWidth`，並定位實際超界元素。於動畫前、中、後，選單開關及切頁後檢查；垂直捲軸占寬不等同 X 軸錯誤。

BrandStory 的垂直淡入與 Swiper 內部位移不應擴大全頁。不要用全頁 `overflow-x:hidden` 作為通過測試的依據。放大文字時，標題、按鈕、卡片與 Footer 應換行或長高。

## 資料與操作流程

- 商品目錄／詳情：長標題、圖片、價格、分類／篩選、排序、分頁、空結果、啟用狀態與預設圖。
- 首頁精選與 Seasonal：候選分離，遵守既有數量及選取規則，不以普通商品靜默補數。
- Article：公開資格、排程邊界、人工入選、排序及補位；列表缺欄位與單篇資料分開判讀。
- 文章分頁：以至少七篇合格文章測每頁六篇、換頁、重新整理、無效／越界頁碼與詳情返回來源頁；檢查標題及返回入口的焦點。
- Garden Tips：候選、三篇選取、各尺寸資訊展開與閱讀入口；觸控／鍵盤不依賴 hover 才取得必要資訊。
- Cart、付款、完成頁與歷次訂單：正常、空資料、載入、失敗等狀態可理解，頁面結果與通知一致；關鍵錯誤不只存在短暫 Toast。
- Article 匯出／匯入：正文完整、任一匯出請求失敗不下載部分資料、整批集合提醒與單篇驗證分開。

## Toast 外觀與生命週期

開發預覽與呼叫方式見 [Toast 文件](TOAST.md)。

| 案例 | 通過條件 |
|---|---|
| 四種狀態、淺色頁／Hero／Header 背景 | 圖示、標籤、邊框與正文可辨認 |
| 短／長／換行／長編號 | 高度自然增長，不橫向溢出，關閉鈕不被擠掉 |
| 單則自動離場 | 進場後保留完整 5／7 秒，再播放離場 |
| hover 停留後離開 | 暫停並接剩餘時間，至少保留 2 秒 |
| hover 與鍵盤焦點重疊 | 只解除其中一個暫停原因不能恢復 |
| 分頁隱藏／視窗失焦 | 返回時正確接續並清理錯誤 hover 原因 |
| 暫停時新增通知 | 原卡片不重播、不偷恢復倒數 |
| 五則排隊 | 同時最多三則，排隊取得完整閱讀時間 |
| 連點關閉、進場中關閉、離場中 hover | 不重複移除、不復活 |
| 鍵盤關閉／手機觸控 | 焦點合理，其他通知不因觸控永久暫停 |
| 減少動態效果 | 純淡入淡出，內容持續可讀 |
| production build | 開發 query 不開啟預覽面板，正式通知仍可用 |

另在矮畫面觀察多則長訊息；數量上限不能保證任意內容高度都可見。

### 自動計時回歸

在含 `package.json` 的專案根目錄，以另一個終端執行：

```powershell
node --test --test-reporter=spec docs/guides/scripts/TOAST-LIFECYCLE-REGRESSION-v2.test.mjs
```

腳本使用 Node 原生測試與模擬時鐘，依相對路徑讀取 `src/features/ui/toastLifecycle.js`，不能單獨抽出執行。修改生命週期或階段時間時，應同步核對測試預期。以本次輸出的測試數、pass 與 fail 作紀錄，不沿用歷史結果。

此腳本驗證計時、暫停、排隊、重複移除與清理，不能取代 React DOM、實際動畫、圖片、焦點、對比或安全區驗證。

## 結果記錄原則

每輪記錄版本／commit、時間、環境、資料來源及實際範圍，分開列出 lint、build、自動回歸、瀏覽器量測、操作證據與使用者接受範圍。

私人逐次結果與補充驗收範圍存放於 Git 忽略的工作筆記；公開方法中不追加個人排程、交接或逐版 ZIP 歷史。任一檢查通過都不能代替其他情境，文件整理也不代表重新執行網站測試。
